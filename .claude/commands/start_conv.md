description: Старт новой сессии - читать SESSION_START_PROMPT и продолжить работу с того места где остановились
---

Это начало новой сессии. Делай в таком порядке:

1. **Прочитай полностью `docs/SESSION_START_PROMPT.md`** - там зафиксировано
   текущее состояние проекта, открытые приоритеты, ключевые файлы и
   `START-OF-SESSION PROTOCOL` со списком всех остальных файлов которые
   нужно прочитать перед стартом. Особое внимание - раздел `ОТКРЫТО`
   и `ПРИВЕТСТВИЕ`
2. Пройдись по `START-OF-SESSION PROTOCOL` - прочитай документы
   которые он перечисляет (progress.md последние 2-3 записи, roadmap.md
   текущий этап, decisions.md последние ADR, gotchas.md, api-contract.md
   бегло, оба `CLAUDE.md` и frontend `ui-guidelines.md`)
3. Проверь актуальное состояние:
   - `git log --oneline -10` (свежие коммиты)
   - `docker ps | grep argumentmap-postgres` (контейнер БД healthy)
   - `lsof -ti:9090` и `lsof -ti:5173` (порты)
4. Прочитай auto memory `MEMORY.md` - там фидбек и пользовательские
   предпочтения накопленные между сессиями
5. **Дай короткое summary** последнего состояния и предложи что делаешь
   дальше (по форме из раздела `ПРИВЕТСТВИЕ` в SESSION_START_PROMPT).
   Не пиши код - жди подтверждения

После апрува - **сразу за работу в режиме автономии** (см.
`feedback_full_autonomy_mode.md` в memory + раздел «РЕЖИМ РАБОТЫ» в
SESSION_START_PROMPT). Не спрашивай по каждому шагу, коммить по ходу.

---

**Напоминание на всю сессию (правило handoff):**

- Если чувствуешь что контекст заполняется (~50%+) или задача не
  влезает в одну сессию - не жди до последнего. Остановись на логичной
  границе (завершённый файл, пройденный тест, закрытая подзадача)
- Перед остановкой обязательно:
  - обнови `progress.md` (новая запись «Сессия N» сверху со
    «Сделано / Решения / Проблемы / Следующий шаг»)
  - обнови `roadmap.md` (отметь `[x]` на закрытых пунктах)
  - обнови `docs/SESSION_START_PROMPT.md` - текущее состояние,
    список открытых TODO, новый приоритет, обновлённое приветствие.
    Это главный handoff-документ - новая сессия читает его first thing
  - сделай финальный handoff коммит (`docs: handoff Сессии N - X`)
  - в «Следующий шаг» в progress.md напиши настолько подробно, чтобы
    новая сессия продолжила без единого вопроса
- Лучше сделать 70% задачи качественно и с чистым handoff, чем 100%
  с оборванным контекстом и потерянными мыслями
