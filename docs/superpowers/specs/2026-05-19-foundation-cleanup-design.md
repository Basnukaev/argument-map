# Foundation cleanup для Claude Code harness — design

**Дата:** 2026-05-19
**Статус:** brainstorm complete, awaiting user review
**Sub-project:** A из программы «Claude Code harness setup» (статья
Anthropic «How Claude Code works in large codebases», май 2026)
**Следующий sub-project:** B (Hooks setup)

## 1. Контекст и motivation

Anthropic в статье от 14.05.2026 описывает harness Claude Code как
последовательность слоёв: CLAUDE.md → hooks → skills → plugins →
MCP. Каждый слой строится на предыдущем. Текущее состояние проекта
argument-map — есть foundation (root + backend + frontend CLAUDE.md,
`.claude/settings.json`, кастомный slash command, Superpowers
plugin), но он накопил долг:

- `backend/CLAUDE.md` 540 строк (target по `doc-hygiene.md` Принцип 2
  — ~150 строк для subdir)
- `frontend/CLAUDE.md` 351 строка (target ~150)
- Нет `.claudeignore` → autogenerated artifacts (target/, node_modules/,
  dist/, frontend/src/shared/api/types.ts) попадают в контекст Claude
- `settings.json` deny rules покрывают только `.env` — нет защиты от
  edit'а autogenerated файлов или design-reference/
- `.claude/commands/start_conv.md` содержит stale references
  (`feedback_full_autonomy_mode.md` — переименован, ПРИВЕТСТВИЕ/ОТКРЫТО
  секции которых уже нет в SESSION_START_PROMPT)

Без foundation cleanup следующие sub-project'ы (hooks, skills) будут
писаться на устаревшую структуру и потребуют переписывания.

## 2. Goals

Success criterion: **navigability**. Claude должен находить нужный
detailed guide за один step, не загружая в контекст 540 строк
backend/CLAUDE.md каждую сессию когда работа касается одной подсистемы.

Конкретные goals:
1. Сжать subdir CLAUDE.md за счёт выноса task-specific деталей в
   `backend/docs/` / `frontend/docs/`. CLAUDE.md остаётся каркасом
   always-on conventions с pointer'ами на детальные гайды.
2. Создать `.claudeignore` — уменьшить шум в контексте от autogenerated
   артефактов.
3. Расширить `settings.json` deny rules — deterministic guards против
   edit'а autogenerated / read-only зон.
4. Починить stale references в кастомных slash commands.

**Microservices-friendly bonus:** вынесенные файлы становятся явными
domain boundaries в документации. OCR pipeline и AI editing — уже
фактически modular подсистемы (свои Spring TaskExecutors, свои state
machines). Когда придёт пора выделять library-service в отдельный
микросервис, `backend/docs/ocr-pipeline.md` и `ai-editing.md` могут
переехать в новый репозиторий без перестройки документации.

## 4. Design decisions

### 4.1. Extraction depth (зафиксировано: **moderate**)

Выносим: task-specific ADR-детали которые нужны только при работе с
конкретной подсистемой.

**Backend кандидаты на вынос:**
- OCR pipeline (ADR-041) — нужно только при работе с
  `lib_pages.ocr_status`
- AI editing (ADR-042) — нужно только при работе с `formatted_content`
- Hadith grades + Authority.type (миграция 47) — специфика hadith
  домена
- Rate limiting (ADR-046) — специфика /auth endpoints
- Actuator security (ADR-048) — специфика /actuator

**Backend остаётся в CLAUDE.md (always-on):**
- Контекст проекта + структура пакетов
- Чек-лист после коммита
- Триггеры ADR/gotcha
- Code review после крупных этапов
- Общие соглашения (Java, Liquibase basics, БД basics, REST basics)
- Pagination pattern (применяется к каждому новому GET-list endpoint)
- Permissions/Audit log (cross-cutting на каждую мутацию)
- Транзакции
- Тесты
- Что НЕ делать
- Cadence verify

**Frontend кандидаты на вынос:**
- Auth (Этап 21.b, ADR-040) — специфика auth flow
- Permissions (Этап 22.b, ADR-043) — специфика RBAC frontend integration
- RTL/i18n блок — заменить ссылкой на уже существующий
  `frontend/docs/i18n-guide.md`

**Frontend остаётся в CLAUDE.md (always-on):**
- Контекст + структура папок
- Чек-лист после коммита
- TypeScript strict правила
- React конвенции (functional components, no premature
  useMemo/useCallback, key from UUID, conditional render для модалок)
- Code review после крупных этапов
- CSS Tailwind правила
- Именование
- Тесты (Vitest + RTL + MSW)
- Что НЕ делать
- Cadence lint/build
- Handoff UI checks
- Playwright ссылка

### 4.3. Pointer format в CLAUDE.md

Заменённая секция в `backend/CLAUDE.md` выглядит так:

```markdown
### OCR (ADR-041)

Pipeline извлечения текста из сканов через Tesseract. Async,
`lib_pages.ocr_status` state machine, graceful degradation если
tesseract не установлен.

**Детали:** `backend/docs/ocr-pipeline.md` (Tess4j integration,
TaskExecutor config, тестирование с @EnabledIf).
```

3 строки в CLAUDE.md (что-зачем-куда) vs 25 строк раньше. Pointer
содержит достаточно контекста чтобы Claude понял **нужно ли** читать
дальше; если задача не касается OCR — pointer пролистывается.

### 4.4. .claudeignore (NEW файл в корне)

```
# Build artifacts
target/
node_modules/
dist/
build/
**/*.log

# Autogenerated - регенерируется через `npm run generate-api`
frontend/src/shared/api/types.ts

# Coverage reports
frontend/coverage/

# IDE
.idea/
.vscode/

# Архив - читать только при поиске исторического контекста
docs/archive/
```

**Намеренно НЕ включено:**
- `frontend/design-reference/` — Claude должен **читать** перед UI
  changes (см. memory `feedback_design_reference_check`). Write
  блокируется через `settings.json` deny (см. 4.5)
- `docs/decisions.md` — большой, но grep'ается по запросу

### 4.5. .claude/settings.json deny rules расширение

Существующий config содержит только `Read(./.env)` / `Read(./.env.*)`.
Дополняем:

```json
{
  "permissions": {
    "deny": [
      "Read(./.env)",
      "Read(./.env.*)",
      "Read(./*.key)",
      "Read(./.claude/settings.local.json)",
      "Write(./frontend/src/shared/api/types.ts)",
      "Write(./frontend/design-reference/**)",
      "Edit(./frontend/src/shared/api/types.ts)",
      "Edit(./frontend/design-reference/**)",
      "Bash(rm -rf /*)",
      "Bash(git push --force *)"
    ]
  }
}
```

Это **deterministic guard rails** — даже если я (Claude) забуду
читать CLAUDE.md и попытаюсь редактировать autogenerated
`types.ts` или `design-reference/` — будет заблокировано. Слабый
прообраз hooks (Sub-project B покроет более тонкую логику типа
«запрет --no-verify»).

### 4.6. start_conv.md fix

Текущий файл ссылается на:
- `feedback_full_autonomy_mode.md` — переименован в
  `feedback_full_autonomy.md`
- Секции «ПРИВЕТСТВИЕ» / «ОТКРЫТО» в SESSION_START_PROMPT.md —
  таких секций больше нет

Полностью переписать под актуальный протокол. Сохранить bottom-секцию
«Напоминание handoff» (always-on reminder).

## 5. Acceptance criteria

1. `backend/CLAUDE.md` ≤ 400 строк (с 540)
2. `frontend/CLAUDE.md` ≤ 250 строк (с 351)
3. Все вынесенные секции имеют 2-3 строчный pointer в CLAUDE.md —
   1-к-1 mapping, ничего не потеряно
4. 4 новых файла в `backend/docs/` (`ocr-pipeline.md`, `ai-editing.md`,
   `hadith-grades.md`, `auth-security.md`). Каждый файл содержит
   **все факты** из соответствующей CLAUDE.md секции дословно — ни
   одна деталь (конфиг env vars, retry policy, state machine,
   тесты) не урезана. Diff CLAUDE.md секции и нового файла должен
   показывать только переформатирование (заголовки markdown,
   возможные секции «Контекст» / «Конфиг» / «Тесты»), не удаление
   информации
5. 2 новых файла в `frontend/docs/` (`auth-integration.md`,
   `permissions-integration.md`) с теми же требованиями полноты
6. `frontend/CLAUDE.md` секция RTL/i18n заменена 3-строчным pointer'ом
   на уже существующий `frontend/docs/i18n-guide.md`
7. `.claudeignore` создан в корне репы и работает (Claude blocked
   от чтения `target/`, `node_modules/`, autogenerated `types.ts`)
8. `.claude/settings.json` обновлён, deny rules покрывают critical
   safety (autogenerated, design-reference, force push, rm -rf /)
9. `.claude/commands/start_conv.md` не содержит stale references,
   работает с актуальным SESSION_START_PROMPT
10. Все backend и frontend тесты проходят (`./mvnw verify` и
    `npm run lint && npm run build && npm run test:run`) — sanity
    check что мы не сломали ничего кроме docs

## 6. Decomposition into atomic commits

```
1. docs(backend): вынести OCR pipeline в backend/docs/ocr-pipeline.md
2. docs(backend): вынести AI editing в backend/docs/ai-editing.md
3. docs(backend): вынести hadith grades в backend/docs/hadith-grades.md
4. docs(backend): объединить rate limit + actuator в backend/docs/auth-security.md
5. docs(frontend): вынести Auth в frontend/docs/auth-integration.md
6. docs(frontend): вынести Permissions в frontend/docs/permissions-integration.md
7. docs(frontend): заменить RTL блок ссылкой на i18n-guide.md
8. chore: добавить .claudeignore
9. chore: расширить .claude/settings.json deny rules
10. docs: переписать .claude/commands/start_conv.md под актуальный SESSION_START_PROMPT
```

Каждый коммит атомарный — один файл выноса + соответствующий pointer
update в CLAUDE.md. Если что-то пойдёт не так — легко откатить
точечно через `git revert <hash>`.

Финальный commit — handoff:
```
11. docs: handoff Sub-project A (Foundation cleanup) closed
```

С summary в `docs/progress.md` записи Сессии 47.

## 7. Risks и open questions

### Risk 1: pointer-секции в CLAUDE.md могут «отсохнуть»
**Mitigation:** Sub-project E (periodic review) добавит quarterly
ритуал проверки `backend/docs/*` файлов на актуальность. Также при
обновлении ADR через `docs/decisions.md` — соответствующий
`backend/docs/<topic>.md` обновляется в том же коммите (это уже
сейчас правило, просто extends на новые файлы).

### Risk 2: лишний файловый шум `ls backend/docs/`
**Текущее количество:** 4 existing + 4 new = 8. Threshold для split
на subdirectory'ы — около ~15 файлов. Пока не достигнут.

### Risk 3: deny rules могут заблокировать **legit** edit
Например `Write(./frontend/src/shared/api/types.ts)` блокирует
manual edit. Это **intentional guard**, а не bug — Claude может
случайно попытаться отредактировать types.ts вручную вместо
регенерации через `npm run generate-api`, что приведёт к расхождению
с backend.

Регенерация работает: `Bash(npm run generate-api)` — отдельная
operation, не Write/Edit. Скрипт сам перезаписывает файл через npm
hook (openapi-typescript), а не через Claude'овский Write tool —
deny не срабатывает.

### Risk 4: stale references в других местах
**Mitigation:** прогон `grep -rn "feedback_full_autonomy_mode\|ПРИВЕТСТВИЕ\|ОТКРЫТО"
docs/ .claude/` после переписывания start_conv.md — выявить
оставшиеся места.

### Open question 1: что делать с `.claude/settings.local.json`
Этот файл содержит большой allow list для Bash commands +
`outputStyle: Explanatory`. Он **не** в git (обычно ignored). Но
там есть references на `/mnt/c/my_folders/projects/argument-map`
(старый путь!). Не трогаем в этом sub-project'е — это твой личный
файл, и его пути не влияют на работу. Можно отдельно почистить
если беспокоит.

### Note: параллельность с другими sub-project'ами
Sub-project D (LSP setup) и Sub-project E (periodic review process)
**не конфликтуют** с A — можно выполнять параллельно. Sub-project'ы
B (Hooks) и C (Skills) **должны идти после** A т.к. они опираются
на финальную структуру CLAUDE.md и `backend/docs/`.

## 8. Что после approval'а этого spec'а

1. Invoke `superpowers:writing-plans` — детальный implementation

3. Verify acceptance criteria из секции 5
4. Commit handoff
5. Update `docs/progress.md` с записью Сессии 47 (или новой если
   контекст переезжает)
6. Move to Sub-project B (Hooks setup) когда готов
