## Blocker для backend `./mvnw verify`

ApplicationContext не загружается в IT тестах из-за commits другого
subagent'а:

```
Caused by: java.lang.IllegalArgumentException:
The Filter class ru.basnukaev.argumentmap.auth.web.security.JwtAuthenticationFilter
does not have a registered order
```

Точка: `SecurityConfig.java:175`:
```java
.addFilterBefore(rateLimitFilter, JwtAuthenticationFilter.class)
```

Spring Security не знает order custom filter (`JwtAuthenticationFilter`)
и потому `addFilterBefore(X, customClass)` падает на startup. Аналогично
строка 183 (`addFilterAfter`).

**Fix должен делать rate-limiting subagent** (его commit `ed313f1`).
Корректный паттерн - использовать встроенный Spring Security filter type
как reference:
```java
.addFilterBefore(rateLimitFilter, UsernamePasswordAuthenticationFilter.class)
.addFilterAfter(jwtAuthenticationFilter, BasicAuthenticationFilter.class)
```

После fix этого блокера baseline восстановится. Наши 45 backend IT тестов
независимы от auth security chain - используют `@SpringBootTest +
TestcontainersConfiguration`, проверяют только сервисы. Они **будут
проходить** после rate-limiting subagent'а fix.
