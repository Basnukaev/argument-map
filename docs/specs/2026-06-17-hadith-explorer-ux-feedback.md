# Hadith Explorer — UX-фидбек ручного теста (2026-06-17)

Источник: ручной прогон Абдулы по narrator-card + hadith-detail + список хадисов
(Сессия 62). **22 пункта.** Каждый — с тимлид-триажем: тип / severity /
approach / нужно ли решение Абдулы. Плюс директива: **#4 = ADR Option B,
реализовать**.

Легенда: 🟢 исполняю сам/делегирую · 🟡 решение Абдулы (вопрос) · 🔵 крупное/спека

---

## РЕШЕНИЯ АБДУЛЫ (форки — спросил отдельно)

- **D1 (статус-таксономия):** CANONICAL/VARIANT (провенанс) vs Слабые/Выдуманные
  (аутентичность, всегда 0). Развести на 2 оси или упростить? + как назвать.
- **D2 (вкладки Текст/Иснад):** убрать «Текст», слить в «Иснад (текст)»→«Текст»?
- **D3 (ИИ-перевод):** добавить сохранение+редактирование перевода?
- **D4 (анонимный доступ):** полный публичный просмотр vs login-gated с мягким
  экраном?

## A. Анонимный пользователь

### A1 🔵 Guest view (= roadmap 49.G). Image #1
**Концерн:** первый заход на фронт без профиля → красный экран «Access token
отсутствует либо истёк». Нужна логика отображения/функционала для анонима.
**Триаж:** крупная фича (49.G в roadmap). Backend `GET /api/v1/**` сейчас
`authenticated()` вне dev; фронт ProtectedRoute гейтит. **Approach:** public GET
endpoints (topics/hadith/library/qa — read-only) `permitAll`; auth-aware UI
прячет write-действия; вместо красной ошибки — публичный контент + ненавязчивый
«Войти» для действий. **D4** — объём (что публично).

## B. Карточка передатчика (`/hadith/narrators/{id}`)

### B2 🟡🟢 Сложночитаемое label:value. Images #3,#4,#6
**Концерн:** в RU непонятно что с чем (кунья + длинный текст в одной колонке —
лейбл оторван от значения); в AR лучше. Нужен материал с дизайнера.
**Триаж:** UX-редизайн `<dl>`-секции NarratorDetailPage. **Approach:** убрать
3-колоночный grid с разнодлинными значениями; перейти на пары лейбл↑/значение↓
или 2-колоночные карточки; длинные значения (кунья-текст) — на всю ширину.
Ждём дизайн-референс от Абдулы — иначе делаю аккуратный default.

### B3 🟢 VARIANT/CANONICAL хардкод в «Передал хадисов». Image #8
**Концерн:** хардкод EN-слов VARIANT/CANONICAL у каждого переданного хадиса;
непонятно что значит, важно ли. **Триаж:** → связан с D1. i18n + tooltip-
объяснение ИЛИ убрать с карточек narrator-transmitted (там провенанс хадиса
вторичен). **Approach по D1.**

### B4 🟢 Тройное повторение + серый прямоугольник. Images #6,#8
**Концерн:** «الصحابي الجليل حافظ الصحابة» повторяется 3×: (1) серый бар под
шапкой, (2) `الطبقة`(поколение)=«الصحابي الجليل», (3) первая оценка учёного.
Серый длинный бар выглядит странно. **Триаж:** дедуп. `gradeText`/
`reliabilityComment` (серый бар) дублирует данные. **Approach:** серый verbatim-
бар показывать ТОЛЬКО если не дублирует tabaqa/первую commentary; либо убрать
(данные уже в секции «Оценки учёных»). Проверить маппинг tabaqa — туда попал
не-поколенческий текст («الصحابي الجليل» — это не طبقة).

### B5 🔵 Виртуальная арабская клавиатура
**Концерн:** нет экранной AR-клавиатуры для тех, у кого нет раскладки.
**Триаж:** новая cross-app фича (поисковые инпуты). **Approach:** компонент
`ArabicKeyboard` (всплывающая раскладка) на поисковых полях (хадисы, рави,
библиотека). Средний объём, отдельная задача.

## C. Detail хадиса (`/hadith/hadiths/{id}`)

### C6 🟢 Гариб-поповер: не влезает, нет скролла, серый текст. Image #11
**Концерн:** клик по гариб-слову с длинным толкованием → поповер вылезает за
экран, внутри нет скролла; текст серый нечитаемый. **Триаж:** баг моей фичи #3.
**Approach:** `max-height: min(70vh, …)` + `overflow-y:auto` внутри поповера;
поднять контраст текста (убрать приглушённый `text-ink-muted`); clamp позиции к
вьюпорту (флипать вверх/в сторону у краёв). **Severity: важно** (свежая фича).

### C7 🟡🟢 Слить «Текст» и «Иснад (текст)». Image #12
**Концерн:** зачем текст (без огласовок) и иснад-текст отдельно? Убрать вкладку
«Текст», переименовать «Иснад (текст)»→«Текст», гариб-подсветку — в иснад-текст
(огласованный). **Триаж:** D2-решение. **Approach (если да):** удалить tab
«Текст» (normalizedMatn); «Иснад (текст)» (огласованный full_text_ar с
кликабельными рави) → «Текст»; перенести гариб-подсветку на огласованный текст
(матчинг с учётом harakat — `normalizeArabic` уже снимает огласовки при
сравнении, рендерим огласованный токен). **Влияет на #3/C16.**

### C8 🟡 CANONICAL + مرفوع хардкод на всех локалях. Image #12
**Концерн:** хардкод; есть ли вообще в науке «Канонические»? **Триаж:** D1.
`status` (CANONICAL/VARIANT) + `hadith_type` (مرفوع/موقوف/مقطوع/قدسي — это
РЕАЛЬНЫЕ термины) рендерятся raw. **Approach:** hadith_type → i18n (марфу'/
маукуф/макту'/кудси с tooltip-определением); status → по D1.

### C9 🟡🟢 ИИ-перевод: сохранять + редактировать. Image #12
**Концерн:** если перевод сделан 1 раз — хранить с возможностью правки; зачем
каждый раз заново ИИ? **Триаж:** D3. **Факт:** перевод УЖЕ кэшируется в
`text_ru`/`text_en` (План 7, cached=true на повторе) — повторного ИИ-вызова
нет. Запрос = (1) показывать сохранённый без кнопки-вызова, (2) **редактировать**
сохранённый (admin-правка text_ru/en). **Approach:** PATCH matn-translation +
edit-UI (ADMIN). Средний.

### C10 🟡🟢 Вкладки как отдельный вид. Images #12 (вся колонка)
**Концерн:** не листать всю инфу вниз; клик по вкладке → открывается как
отдельный вид страницы. **Триаж:** UX-модель. Сейчас вкладки = scroll-to-section
(всё стекается). **Approach:** настоящий tab-switcher — клик показывает ТОЛЬКО
секцию. Граф иснада — закрепить в каждой (или своя вкладка). Согласовать с D2/C18.

### C11 🟢 Turuq-легенда: overflow + не кликабельна. Image #13
**Концерн:** «Все пути (127)» — список «Цепи передачи» слева не влезает, нет
скролла; нельзя кликнуть на цепь чтобы подсветить ЕЁ путь в графе. **Триаж:**
доработка моей #2. **Approach:** легенде `max-height + overflow-y:auto`; клик по
строке цепи → highlight рёбер/узлов этого санада в графе (hover/active-стейт +
dim остальных). **Severity: важно.**

### C12 🟢 Макс. зум графа ограничен
**Approach:** поднять `maxZoom` у React Flow в SanadGraph (и графе аргументации).

### C13 🟢 Полноэкранный режим графа
**Approach:** кнопка fullscreen (Fullscreen API / расширение контейнера) в
graph-chrome. Переиспользуемо для argument-map.

### C14 🔵 Запутанный граф + PNG без лимита разрешения. Image #14
**Концерн:** при многих связях узлы пересекаются — граф должен быть понятным;
PNG-картинка в неограниченном разрешении. **Триаж:** (а) layout — ELK/dagre
тюнинг для иснад-сети (анти-overlap, spacing), средний; (б) PNG-экспорт высокого
разрешения (`toPng` с `pixelRatio`/bounds, без вьюпорт-кропа). Разбить на 2.

### C15 🟡 Иснад с 1 сборником — баг или импорт? Image #15
**Концерн:** граф показывает один collection-узел («المستدرك», «вы здесь») —
сломан иснад или мис-импорт? **Триаж:** investigation. **Approach:** проверить
конкретный хадис (turuq с одной цепью без рави? или рендер не строит цепь из
narrators[]?). Может быть валидно (одиночная передача) ИЛИ баг построения.
Диагностировать на данных.
**ДИАГНОЗ (С62):** НЕ баг рендера. Хадис `46700d79…` (المستدرك, VARIANT) =
такхридж аль-Хакима «هذا حديث صحيح على شرط مسلم» — 0 структурных рави (hd_sanads
пуст), isnad-текст есть (335 симв.), но без `<a class=rawy>`-тегов → парсер честно
извлёк 0. Корпус-wide: **996 (~3%) с 0 sanad_narrators** = VARIANT-такхридж без
цепи. Граф КОРРЕКТЕН. **ФИКС (queue, после graph-executor):** empty-state в
SanadGraph при 0 рави («вариант/такхридж без отдельной цепи — см. текст иснада»).

### C16 🟢 Гариб-слова со знаками препинания. Image #16
**Концерн:** в некоторых гариб-словах знаки пунктуации (`الأكبر،` с запятой).
**Триаж:** баг матчинга #3 — reference содержит/захватывает пунктуацию.
**Approach:** в `highlightGharib` тримить арабскую/латинскую пунктуацию
(`، . ؛ :` и т.п.) с границ reference и токена перед сравнением/рендером.

### C17 🟡🟢 «Параллельные тексты»: смысл + diff-подсветка. Image #17
**Концерн:** зачем параллельные тексты? почему без подсветки различий с текущим?
**Триаж:** sibling-matns (С59) показывает матны параллельных передач. Запрос:
diff-highlight отличий от текущего матна. **Approach:** word-level diff
(текущий vs sibling), подсветить расхождения. Объяснить назначение секции
(подзаголовок). Средний.

### C18 🟢 Хедер вкладок крупнее/заметнее. Image #12
**Approach:** увеличить tab-бар (размер, контраст, активный стейт) — связано
с C10.

### C19 🟡 Статус-фильтры Канонические/Варианты/Слабые/Выдуманные. Images #18,#20
**Концерн:** есть ли в науке «Канонические/Варианты»? хардкод. **Триаж:** D1
(ядро). Фильтры daif/maudu всегда 0. **Approach по D1.**

### C20 🔵 Пагинация «Показать ещё» — переосмыслить везде. Image #20
**Концерн:** «Показать ещё» не нравится; нормальная пагинация во всех местах.
**Триаж:** UX-паттерн cross-app. **Approach:** предложить единый паттерн —
нумерованная пагинация ИЛИ infinite-scroll с «загрузка…» + счётчик «N из M»;
применить к hadith/narrator/book/qa-листам. Согласовать паттерн.

### C21 🟡 Выдуманные=0, Слабые=0 — ок? Images #21,#22
**Концерн:** в категориях нет данных; в сборниках не будет таких хадисов?
**Триаж:** = D1. Сейчас 0 by design (status не несёт daif/maudu). Daif РЕАЛЬНО
есть в корпусе (Муснад Ахмада и др. содержат слабые) — но классификация лежит в
рулингах (`hd_rulings.ruling_text`), не в `status`. Решается с D1 (аутентичность
из рулингов).

## #4 — Admin-форма «Оценка учёного» (ADR Option B — РЕАЛИЗОВАТЬ)
**Директива Абдулы:** Option B. Связать `hd_hadiths`↔`sources` (гарантированный
`source_id`, sourceType=HADITH) и переиспользовать `hadith_grades`; detail ЧИТАЕТ
из `hadith_grades` (JOIN), а не из `metadata.grades`. **Факт:** колонка
`hd_hadiths.source_id` УЖЕ существует — проверить заполненность (если null →
backfill/lazy-create source на запись оценки). **Approach:** ADR-062 + миграция
(backfill source_id или lazy) + detail GET читает hadith_grades + форма
(authority SCHOLAR + grade enum + citation + note → POST `/sources/{id}/grades`)
+ gate роли. Independent review.
