# Платформа для исламской науки

> Внутреннее техническое имя репозитория - `argument-map` (по
> историческим причинам), но это **платформа** цифровых инструментов
> для исламских учёных и студентов. Argument-map - первое приложение
> на этом фундаменте, не центральный продукт. См. [`docs/vision.md`](docs/vision.md)
> для целевого видения

## Что это

Платформа цифровых инструментов для **исламских учёных и студентов**.
Главный принцип - **точная атрибуция**: любая цитата в любом
приложении имеет автора (`Authority`), труд (`Source`/`Book`), точное
место (`location`), степень достоверности

```
                    ┌─────────────────────────┐
                    │    library (книги +     │
                    │    цитирование)         │
                    └────────┬────────────────┘
                             │
              ┌──────────────┼──────────────┐
              │              │              │
       ┌──────▼─────┐  ┌────▼─────┐  ┌─────▼──────┐
       │ argument-  │  │   Q&A    │  │  будущие   │
       │   map      │  │          │  │ приложения │
       └────────────┘  └──────────┘  └────────────┘
```

## Текущее состояние

- **Argument-map**: рабочее приложение с CRUD узлов/связей,
  drag-create, reconnect edges, секцией «Опора» (mustanad - то на
  что опирается тезис) с library + freeform citation, structured
  academic citation готов на бэке (ADR-028), frontend блочный
  рендер - в работе (Этап 20.f)
- **Library**: рабочая - shamela import, BookListPage, BookReader с
  RTL/naskh, PDF Viewer source-agnostic с MinIO storage, CitationPicker
- **Q&A**: в roadmap (Этап 19), валидация платформенного фундамента
  после library

См. [`docs/roadmap.md`](docs/roadmap.md) для актуального плана.
Закрытые этапы свёрнуты в одну строку, активные имеют чек-лист

Решение Сессии 23 - один SPA в `frontend/` вместо monorepo с `apps/*`
+ `packages/*`. Один разработчик, один стек, один домен с навигацией -
не нужны отдельные Vite-серверы и сложности workspaces hoisting.
Когда возникнет конкретная необходимость (другая команда / разные
домены / огромный бандл) - вернёмся к monorepo

Cleanup marathon в Сессии 25 (ADR-022) разнёс старый плоский
`src/components/` + `src/pages/` по `src/apps/{argument-map,library,admin}/` +
`src/shared/`

## Технологии

- **Backend**: Java 21, Spring Boot 3.5, JDBC Template (без JPA),
  PostgreSQL 16, Liquibase
- **Frontend**: React 19, TypeScript strict, Vite 6, Tailwind v4,
  React Flow (для argument-map), Zustand 5, openapi-typescript
- **Тесты**: JUnit 5 + Testcontainers на бэке, Vitest + RTL + MSW
  на фронте
- **Library расширения**: Apache Tika (планируется для PDF/EPUB
  upload), Tess4j (планируется для OCR), MinIO (готов, через AWS
  SDK v2), react-pdf (для PDF viewer)

См. [`docs/architecture-platform.md`](docs/architecture-platform.md)
для детального описания стэка и обоснований

## Работа с Claude Code

Claude Code работает по всему дереву - бэк, фронт, корневая
документация. Стартовый промпт для новой сессии:
[`docs/SESSION_START_PROMPT.md`](docs/SESSION_START_PROMPT.md)

Memory Claude Code хранится в
`~/.claude/projects/-mnt-c-my-folders-projects-argument-map/memory/`
с feedback-памятками (decision authority, WSL-only, no frequent
builds, и т.д.)
